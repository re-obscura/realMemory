# realMemory: установка и использование командой

Пошаговая инструкция: от `pip install` до командной памяти с координатором,
публикациями и живыми пирами. Рассчитана на локальную команду в доверенной
сети (LAN/VPN). Модель доверия и границы — в
[TEAM.md §Упрочнение v0.8.1](TEAM.md).

---

## 1. Требования

- **Python 3.11–3.14** (3.10 не поддерживается).
- Windows / Linux / macOS. В примерах — Windows; отличия для Linux отмечены.
- `git` — по нему определяется identity по умолчанию.
- Для семантического эмбеддера: ~240 МБ на модель (скачивается один раз),
  ~580 МБ RAM процессу MCP-сервера.

## 2. Установка (каждый участник)

```bash
git clone https://github.com/re-obscura/realMemory.git
cd realMemory
python -m venv .venv
# Windows:           .venv\Scripts\activate
# Linux/macOS:       source .venv/bin/activate
pip install -e ".[mcp,local,team,dev]"
```

Что даёт каждый extra:

| Extra | Зачем | Без него |
|---|---|---|
| `mcp` | MCP-сервер для ZCode / Claude Code (fastmcp) | тула агента не будет |
| `local` | семантический эмбеддер fastembed (ONNX, локально) | откат на hashing — без семантики |
| `team` | TUI публикаций (Textual), политика (yaml) | CLI команды без `ui` |
| `dev` | pytest, ruff, mypy | разработка |

Смок-тест после установки:

```bash
pytest                # 178 тестов; TUI-смок пропустится, если textual не встал
```

## 3. Каталог памяти и identity

Мозг — это **каталог с `memory.db`**, по одному на человека, вне репозиториев:

```
D:\realmemory\rmd          # Windows-пример
~/.local/share/realmemory  # Linux-пример
```

Identity автора записей (первый непустой источник):

1. `$REALMEMORY_IDENTITY`;
2. файл `~/.realmemory/identity` (первая непустая строка);
3. `git config user.name`.

Задать один раз:

```bash
# Windows: setx REALMEMORY_IDENTITY "максим"
mkdir %USERPROFILE%\.realmemory & echo максим > %USERPROFILE%\.realmemory\identity
```

## 4. Подключение к ZCode / Claude Code

### 4.1 MCP-сервер

В пользовательском конфиге MCP (user scope):

```json
"realmemory": {
  "type": "stdio",
  "command": "D:\\projs\\realMemory\\.venv\\Scripts\\python.exe",
  "args": ["-m", "realmemory.api.mcp_server",
           "--path", "D:\\realmemory\\rmd",
           "--embedder", "local"]
}
```

- `--embedder local` — fastembed MiniLM (RU+EN), пороги калибруются сами.
  `hashing` — без модели, для тестов. **Эмбеддер фиксируется в базе:**
  открыть базу другим — отказ с внятной ошибкой, векторы разных моделей
  несравнимы.
- `--namespace work` — отдельный мозг в подкаталоге (изоляция контекстов);
  обычно не нужен, скоупы справляются.
- Скоуп проекта определяется автоматически: `REALMEMORY_PROJECT` →
  `ZCODE_PROJECT_DIR` → рабочая директория с `.git`. `recall` видит свой
  проект + `global`, чужие проекты не протекают. Проверка — тул `introspect`.

### 4.2 Автоматизация: бриф на старте, сон в конце

В конфиг хуков клиента:

```json
{
  "hooks": {
    "SessionStart": [{"hooks": [{"type": "command",
      "command": "D:\\projs\\realMemory\\.venv\\Scripts\\python.exe -m realmemory.hook_cli brief --path D:\\realmemory\\rmd"}]}],
    "Stop": [{"hooks": [{"type": "command",
      "command": "D:\\projs\\realMemory\\.venv\\Scripts\\python.exe -m realmemory.hook_cli sleep --path D:\\realmemory\\rmd"}]}]
  }
}
```

- `brief` — инжектит краткое состояние памяти (~600 символов) в начало сессии;
  модель эмбеддера не грузит.
- `sleep` — консолидация после каждого ответа; троттлится по состоянию базы,
  ничего не менялось — выходит за миллисекунды.
- Хуки и MCP-сервер работают с одной базой одновременно: всё состояние в
  SQLite (WAL + `BEGIN IMMEDIATE`), ничего не теряется.
- Отказ хука не молчит: строка в stderr сессии + событие `hook_error` в отчёте.

## 5. Инструменты агента — шпаргалка

| Тул | Когда | Ключевое правило |
|---|---|---|
| `recall(query, k, project)` | перед утверждениями о пользователе/проекте | `abstained=true` — сказать «не помню», не выдумывать |
| `memorize(text, kind, related_ids, project)` | после решения/факта | выводы, а не реплики диалога; «как решили» вместо «обсуждали» |
| `reflect(memory_ids, reward)` | после использования recalled | без этого затухание и промоция работают вслепую |
| `revise(old_id, new_text)` | реальность изменилась | старый след остаётся связанной историей; его публикации отзываются автоматически |
| `introspect()` | проверить проект/объёмы | один вызов — видно текущий скоуп |
| `dream_log()` | как ведёт себя память со временем | retention, возраст, счётчики |
| `recall_team(query, author, project)` | «что известно команде про X» | у каждого хита автор и возраст — упоминать свежесть |

Дисциплина видна в отчёте: доля `reflect` на `recall` ниже ~0.1 — память
учится вслепую.

## 6. Наблюдаемость и эксплуатация

```bash
python -m realmemory.report --path D:\realmemory\rmd [--json report.json]
```

Рост по типам/скоупам, история решений гейта, воздержания, латентность,
что подкрепляется/угасает, отказы хуков.

- **Бэкапы**: перед каждым «сном» консистентная копия в `<память>\backups\`,
  последние 10, троттлинг 6 часов. Любая миграция схемы сначала делает
  страховочную копию.
- **Апгрейд версии**: `git pull` → `pip install -e ".[mcp,local,team,dev]"` →
  перезапустить MCP-сервер. Миграции схемы применяются при открытии базы
  автоматически.

## 7. Командный слой

Личное по умолчанию: `memorize`/`recall` не отправляют ни байта наружу.
Всё, что покидает машину, — явные публикации из локального registry
(tombstones для отзывов), отфильтрованные политикой.

### 7.1 Общий токен

Договоритесь о секрете и задайте его **каждому участнику и координатору**
(не в репозитории, не в чате — переменная окружения):

```bash
setx REALMEMORY_TEAM_TOKEN "<длинный-случайный-секрет>"
```

Привязка координатора/пира к адресу вне `127.0.0.1` **без токена отклоняется
при старте** (fail-closed).

### 7.2 Политика `~/.realmemory/team.yaml`

```yaml
identity: максим
coordinator: http://192.168.1.10:8400   # kill-switch: нет адреса — нет сети
token_env: REALMEMORY_TEAM_TOKEN
auto_sync: false                        # true = доставка публикаций после каждого сна
default_kinds: [semantic]               # что считается публикуемым
min_reinforcements: 2                   # устойчивость факта перед публикацией
projects:
  - name: realmemory                    # короткая форма: только имя
  - name: shop-backend
    kinds: [semantic, episodic]
    min_reinforcements: 3
never:                                  # fail-closed, сильнее всего остального
  meta_tags: [private, secret, credentials]
  text_patterns:
    - '(?i)\bapi[_-]?key\b\s*='
    - '(?i)\bpassword\s*[:=]'
    - '(?i)секретн'
    - '(?i)\bпароль\s*[:=]'
```

Never-правила не переопределяются ничем: кандидат под попадание отменяет
весь пакет публикации.

### 7.3 Координатор (один хост на команду)

Пассивный сервис: хранит **только явно опубликованное** + эфемерные
presence-хартбиты (TTL 90 c), в локальные базы не пишет.

```bash
# на выделенном хосте/машине одного из разработчиков
REALMEMORY_TEAM_TOKEN=<секрет> python -m realmemory.team.coordinator \
    --data D:\realmemory\coord_data --host 0.0.0.0 --port 8400
```

- Для постоянной работы — автозапуск: Windows — Task Scheduler («при
  входе»/службой через NSSM), Linux — systemd unit.
- Открыть порт 8400 в файрволе. Доступ из интернета — только через VPN.

### 7.4 Пир-эндпоинт (опционально, на машине каждого)

Живой доступ к «опубликованному подмножеству» напрямую, минуя кэш:

```bash
REALMEMORY_TEAM_TOKEN=<секрет> python -m realmemory.team serve \
    --path D:\realmemory\rmd --host 0.0.0.0 --port 8410
```

Демон сам шлёт presence-хартбиты с адресом (если настроен координатор).
Приватность конструктивная: личные следы вне публикаций не попадают в
кандидаты ни на одном шаге (JOIN memories × publications).

### 7.5 Публикация и отзыв

```bash
python -m realmemory.team status --path D:\realmemory\rmd [--json]
python -m realmemory.team ui     --path D:\realmemory\rmd   # интерактивно
python -m realmemory.team sync   --path D:\realmemory\rmd   # доставить координатору
python -m realmemory.team recall-team --path D:\realmemory\rmd "запрос" [--author X] [--json]
```

TUI (`ui`): карточки проектов с РЕАЛЬНЫМИ цифрами (активных / кандидатов /
never-block / опубликовано), превью живых текстов кандидатов до публикации,
переключатель «что можно» правит только политику; публикация — отдельное
действие по выбранным id. Клавиши подсказаны в интерфейсе
(`space`/`s`/`p`/`u`/`r`/`q`).

Минимальный путь команды: включить проект в политике → `ui` → выбрать
кандидатов → `p` (опубликовать в registry) → `sync` (или `auto_sync: true`).

Автоотзывы: след забыт GC или исправлен через `revise` — tombstone ставится
локально **сразу**, доставляется при следующем sync. От protocol отзыва не
отказываемся никогда.

### 7.6 Поиск по команде

Агент использует тул `recall_team` (появляется только при настроенном
координаторе). Порядок честности: presence → живые пиры (таймаут 1.5 с,
до 6 штук) → кэш координатора; дедуп по (author, text); у выдачи —
`max_age_s` (устаревание худшего попадания). Несовпадение эмбеддеров —
честный 409, а не бессмысленный косинус: держите версии `fastembed`
одинаковыми (`pip install 'fastembed>=0.8,<0.9'`).

## 8. Если что-то не так

| Симптом | Причина / действие |
|---|---|
| «эмбеддер базы …, а открывается с …» | база писалась другим эмбеддером; откройте исходным или начните новый каталог |
| `recall_team`: `embedder_mismatch` (409) | у коллеги другая версия fastembed/модели — синхронизировать |
| координатор недоступен в отчётах | проверьте `http://<host>:8400/health`, токен, файрвол; sync доедет сам позже |
| агент пишет не в тот проект | `introspect` — там виден текущий скоуп; задайте `REALMEMORY_PROJECT` |
| хук упал | строка в stderr + `hook_error` в `report`; чаще всего нет пакета/пути в конфиге хука |
| «привязка к 0.0.0.0 без общего токена отклонена» | так и задумано: задайте `REALMEMORY_TEAM_TOKEN` или слушайте 127.0.0.1 |
| публикация отменена целиком | never-правило сработало fail-closed; проверьте `status`/`policy` |

## 9. Границы доверия — кратко

- Общий токен = полное доверие участникам; атрибуция на проводе не
  подписана (криптографическая подпись — отдельный этап, см. TEAM.md).
- Транспорт — открытый HTTP: между офисами только через VPN/WireGuard.
- Координатор хранит опубликованные тексты и векторы — это его функция.
  Личное (неопубликованное) не покидает машину ни при каких вызовах.
